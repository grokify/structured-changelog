# Release Notes - v0.17.0

## Overview

This release implements the **RMI trailer flow** ([INIT-SCHANGELOG-001](https://github.com/grokify/structured-changelog/tree/main/docs/specs/initiatives/INIT-SCHANGELOG-001)): `Refs: RMI-<SLUG>-<NNN>` git trailers on commits now flow through `parse-commits` into **pre-populated `rmis`** on generated changelog entries, so the human curates roadmap traceability rather than transcribing it.

## Highlights

- `Refs:` trailers on commits flow into per-commit `rmis` and pre-populated entry `rmis`
- New plural `rmis` field on entries, preferred over the legacy singular `rmi`

## New Features

### Trailer Parsing (`parse-commits`)

`parse-commits` now extracts roadmap item IDs (`RMI-<SLUG>-<NNN>`) from a commit's `Refs:` git trailers and carries them as `rmis` on each parsed commit, in both TOON and JSON output. Multiple trailers per commit and multiple IDs per trailer are supported and deduplicated. The existing `#123` issue-ref extraction is unchanged.

### Plural `rmis` Field

Entries gain an additive `rmis []string` field and a `WithRMIs` builder:

```go
entry := changelog.NewEntry("Add streaming support").
    WithRMIs("RMI-MYREPO-042", "RMI-MYREPO-044")
```

A curated entry often summarizes several commits spanning multiple RMIs, which the singular `rmi` cannot express. The legacy `rmi` is retained for back-compatibility and treated as a one-element `rmis`.

### Pre-Populated Generation

`init --from-tags` now fills each generated entry's `rmis` from the underlying commits' trailers (deduplicated, sorted). `initiative` is never auto-populated — with an RMI present it is derivable downstream.

### Validation

`schangelog validate` (rich mode) adds two warnings:

- **W006** — a string in `rmis` is not a well-formed `RMI-<SLUG>-<NNN>` ID.
- **W007** — a singular `rmi` disagrees with `rmis`.

## Convention

- **Populate `rmis`** on entries tied to roadmap items.
- Set **`initiative` only** for entries with no RMI (an RMI resolves to its initiative downstream, so storing both invites drift).
- Carry `Refs: RMI-<SLUG>-<NNN>` trailers on commits and let `parse-commits`/`init` do the population.

This release dogfoods the convention: its own changelog entries carry `rmis`.

## Schema

The `Entry` definition in `changelog-v1.schema.json` gained the PRISM roadmap block (`rmis`, plus the previously missing `rmi` and `initiative`). Verified with `schemakit lint --property-case camelCase`.
